# QA-P0-01 前端主流程回归清单

## 1. 目标

验证当前 mock 闭环在前端可以稳定演示，覆盖以下四条主链路：

- 预警生成任务
- 任务指派与状态流转
- 审批回写任务状态
- 日报 / 周报生成

## 2. 执行前提

- 启动前端：`npm run dev`
- 初始角色：`管理员`
- 测试环境：使用当前仓库内 mock 数据，不依赖后端接口

## 3. 用例清单

### Case 1 预警生成任务

- 步骤：
  - 进入 `预警中心`
  - 在一条尚未存在任务的预警项上点击 `生成任务` 或 `立即处理`
  - 页面跳转到 `AI 任务中心`
  - 搜索对应来源对象
- 期望结果：
  - 能跳转到 `AI 任务中心`
  - 任务列表中出现对应来源对象的新任务
  - 如果该来源对象已有未关闭任务，则预警中心显示 `查看任务` 而不是重复生成
  - 活动日志中有 `创建任务` 或 `跳过重复任务`

### Case 2 任务指派与状态流转

- 步骤：
  - 进入 `AI 任务中心`
  - 选择任一任务
  - 修改责任人为其他角色
  - 点击 `开始处理`
  - 点击 `标记完成`
  - 点击 `关闭任务`
- 期望结果：
  - 责任人变更立即生效
  - 状态按 `open / in_progress / done / closed` 正常流转
  - 详情区显示触发依据、证据、审批记录、活动日志
  - 活动日志中依次记录 `重新指派`、`更新任务状态`

### Case 3 审批回写任务状态

- 步骤：
  - 在 `AI 任务中心` 选择一条任务并点击 `发起审批`
  - 进入 `AI 审批台`
  - 选择该审批项并填写审批意见
  - 分别执行：
    - `批准并继续`
    - `驳回退回任务`
    - `要求补充信息`
  - 回到 `AI 任务中心` 查看对应任务
- 期望结果：
  - 发起审批后任务状态变为 `pending_approval`
  - 批准后任务状态回写为 `in_progress`
  - 驳回后任务状态回写为 `open`
  - 要求补充信息后任务状态回写为 `open`
  - 审批意见显示在审批详情和任务审批记录中
  - 活动日志中出现 `发起审批`、`处理审批`

### Case 4 日报 / 周报生成

- 步骤：
  - 进入 `AI 报告中心`
  - 点击 `生成日报`
  - 点击 `生成周报`
  - 返回 `AI 驾驶台`
- 期望结果：
  - 报告中心新增对应报告卡片
  - 报告卡片展示标题、创建时间、摘要和 highlights
  - 驾驶台指标中的报告数量同步增加
  - 活动日志中出现 `生成报告`

### Case 5 普通成员权限回归

- 步骤：
  - 在左侧栏将角色切换为 `普通成员`
  - 进入 `预警中心`、`AI 任务中心`、`AI 审批台`、`系统设置`
- 期望结果：
  - `预警中心` 不显示生成任务按钮，只显示只读提示或查看任务
  - `AI 任务中心` 不显示指派、状态更新、发起审批、关闭任务操作
  - `AI 审批台` 不显示审批按钮
  - `系统设置` 不显示新增、编辑、删除、配置类操作

## 4. 当前验证结果

- `npx tsc --noEmit`：通过
- 当前仓库未接入自动化测试框架，因此本轮以手工回归清单为主
- 建议后续在 `QA-P1` 阶段引入组件级或页面级自动化测试

## 5. 结论

- 当前前端已具备 QA-P0-01 所需的主流程验证条件
- 可以作为 Sprint 内人工回归基线继续复用
