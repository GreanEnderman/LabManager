# LabManager AI员工项目同步报告

更新日期：2026-04-22

## 一、当前做的是什么 AI 员工

当前开发的不是自由聊天式助手，而是一个面向实验室业务流程的“AI员工 / 数字协调员”。

它的职责是围绕实验室日常管理主链路开展工作：

巡检发现问题 -> 生成标准事件 -> 创建任务 -> 推动处理 -> 发起审批 -> 生成报告 -> 留下审计记录

当前 AI 员工主要服务两类实验室场景：

- 化学品 / 试剂进销存管理
- 仪器设备维护与异常处理管理

V1 阶段的 AI 员工核心定位如下：

- 不是聊天机器人
- 不直接操作数据库
- 不直接替代人工做高风险决策
- 先基于规则发现问题和推动流程闭环
- 所有动作必须可追踪、可审计、可回溯

目前已经落地的三类核心事件包括：

- 低库存事件 `low_stock`
- 超期维护事件 `maintenance_overdue`
- 异常设备事件 `equipment_fault`

基于这些事件，AI 员工会把实验室里“原本需要人主动盯着”的事项，转成可执行、可跟踪、可审批、可沉淀报告的流程任务。

## 六、风险 / 卡点：是否有技术难题或需要外部协助

当前项目没有阻断主链路的致命卡点，但存在以下几个需要提前管理的风险：

### 1. 正式 PDF 导出方案尚未落地

当前报告导出还是“打印页 + 浏览器另存为 PDF”的最小实现。

风险：

- 样式一致性受浏览器影响
- 无法直接作为标准化服务端投递附件
- 后续若接正式邮件投递，需要补标准 PDF 生成链路

建议：

- 尽快确定正式 PDF 方案
- 明确是前端打印导出路线，还是后端服务端生成路线

### 2. 邮件发送仍是演示级能力

当前发送能力更偏“功能演示闭环”，尚未进入生产可用状态。

风险：

- 真实投递失败率、退信、权限等问题尚未验证
- 发送失败后自动重试与告警未完成
- 附件格式和邮件模板还未固化

需要外部协助：

- 邮件网关 / SMTP / 企业邮箱配置支持
- 真实发件账号、测试环境、白名单支持

### 3. 文档与代码存在同步偏差

当前 `AGENTS.md` 对阶段描述仍偏旧，项目真实进度以 `docs/ai-executable-backlog.md` 和 `docs/project-sync-status.md` 为准。

风险：

- 对外同步时容易低估或误判当前完成度
- 团队成员可能按旧文档理解版本边界

建议：

- 尽快统一一版对外口径文档
- 减少“旧阶段文档”和“当前实际进度”并存带来的认知差

### 4. P2 进入生产化后，测试深度需要提升

当前主链路能演示，但如果要进入真实试运行，测试重点需要从“功能存在”升级到“稳定可用”。

风险：

- 高频事件与批量导入下的稳定性未验证
- 权限边界和审计追踪还缺专项测试
- 报告投递缺完整端到端压测

### 总体判断

当前风险更多是“从演示版走向生产版”的风险，而不是“项目做不出来”的风险。

也就是说：

- V1 演示闭环已具备
- 当前卡点主要在正式投递、正式 PDF、通知与稳定性增强
