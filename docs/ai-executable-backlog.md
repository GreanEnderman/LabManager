- `AGENTS.md` 提供项目约束、边界和执行原则，但旧阶段叙述不应覆盖当前实现真相。

- 讨论时请显式区分四层事实：`当前实现`、`TS 原型边界`、`Python 目标栈`、`迁移窗口`。

## 1. 使用说明

本文档将现有需求、设计、工作流和开发计划收敛为可以直接开工的 backlog。

任务按以下维度组织：

- 优先级：`P0 / P1 / P2`
- 职能域：`前端 / 后端 / AI / 测试`
- 每项任务包含：目标、关键产出、验收标准、依赖关系

执行原则：

- 先闭环，再增强
- 先规则，再智能
- 先 mock，再真实接口
- 先低风险自动化，再高风险审批执行

## 2. 版本范围

### 2.1 V1 必做范围

- 三类事件：低库存、超期维护、异常设备
- AI 驾驶台
- AI 任务中心
- AI 审批台
- AI 报告中心
- 任务状态机与审批状态机
- 规则驱动事件生成
- 活动日志与审计留痕
- 前端 mock 闭环
- 后端任务中枢与基础接口

### 2.2 V1 暂不包含

- 自由聊天式通用 AI 助手
- 自动采购下单
- 自动停用设备
- 复杂预测模型
- 跨多日自主规划执行

## 2.3 版本收敛视图

### V1 必做

- 前端 AI 闭环：`FE-P0-01 ~ FE-P0-09`
- 后端任务中枢：`BE-P0-01 ~ BE-P0-07`
- 规则与 LangGraph 最小主链路：`AI-P0-01 ~ AI-P0-05`

- 说明：V1 以“巡检 -> 建任务 -> 跟进 -> 审批 -> 报告”的主链路闭环为准，不纳入在线导入、PDF 正式导出、邮件投递。

### V1.5 可做

- 报告中心增强与详情统一：`FE-P1-01`, `FE-P1-04`
- 策略配置与 SLA 增强：`FE-P1-02`, `FE-P1-03`, `BE-P1-01 ~ BE-P1-04`
- 在线导入闭环：`FE-P1-05`, `FE-P1-06`, `BE-P1-05`, `BE-P1-06`, `QA-P1-04`
- Agent 能力增强：`AI-P1-01 ~ AI-P1-05`
- 联调与规则验证：`QA-P1-01 ~ QA-P1-03`
- 说明：V1.5 解决“从可演示到可上线试运行”的关键缺口，尤其是在线录入/导入、配置持久化、SLA 和真实报告生成。

### P2 延后

- 正式 PDF 导出：`FE-P2-01`
- 多角色工作台：`FE-P2-02`
- 报告发送配置与记录：`FE-P2-03`
- Excel 导入导出联动 AI：`BE-P2-01`
- 通知中心与记忆层：`BE-P2-02`, `BE-P2-03`
- 主管邮箱映射、PDF 邮件投递、失败重试：`BE-P2-04 ~ BE-P2-06`
- AI 深化与月报：`AI-P2-01 ~ AI-P2-04`
- 稳定性与审计专项验证：`QA-P2-01 ~ QA-P2-04`
- 说明：P2 主要处理体验增强、运营投递、深度智能和高可用要求，不阻塞 V1 / V1.5 主链路上线。
